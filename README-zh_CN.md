## 🌟 模组简介

**酒狐的魔法书** 让《车万女仆》里的女仆真正成为法师：把法术书放进她的饰品栏，她就会在战斗中按局势自己挑法术、盘算魔力、避开冷却、走位拉扯，并在使用 GeckoLib 模型时播放咏唱动作。

除了「让女仆会施法」这条主线，模组还提供：

- **酒狐巫法**——一个自带伤害类型与专属属性的独立学派，主打**玩家与女仆的配合**：玩家起手、女仆接力，两边一起打出来的收益远高于各打各的；
- **附属兼容**——为 10 个铁魔法附属模组的数百个法术做了女仆行为分类，装了就能用，没装也不会报错。

至于名字：咏唱动画只有 GeckoLib 模型的女仆才播得出来，而「酒狐」正是这样一款女仆模型。

## ⚡ 快速上手

1. 装好前置：**车万女仆（Touhou Little Maid）** + **铁魔法（Iron's Spells 'n Spellbooks）**，以及它们各自的前置（Curios、GeckoLib）。
2. 装上本模组。
3. 给女仆一本刻好法术的**法术书**，放进她的**饰品栏**；或者给她一件**注魔的武器 / 盔甲**。
4. 打开女仆 GUI，把任务切到 **法术攻击** 或 **法术支援**。
5. 打一架看看——保持「法术战斗中显示法术名称」开着（默认开），就能在她头顶看到当前施放的法术。

## 🧙 女仆施法

### 施法媒介

女仆的**主手、盔甲栏、女仆饰品栏、Curios 栏**都会被扫描，其中任何「法术容器」（法术书、注魔武器、注魔盔甲）里的法术都会进入她的法术表。

- 多本法术书**只有一本生效**（与玩家一致）；注魔装备不受此限，可以叠加。
- 法术等级 = 法术本身的等级 + 装备上的亲和（Affinity）加成。
- **不属于任何行为分类的法术会被直接忽略**——这是「女仆就是不放某个法术」最常见的原因，见[七个行为分类](#七个行为分类)。
- 女仆的装备一变动，法术表立刻重算；用 `/reload` 更新法术标签后，已加载的女仆也会跟着重扫。

### 两种任务

| 任务 | 会用的法术分类 | 作用目标 |
|---|---|---|
| **法术攻击** | 攻击 / 防御 / 移动 / 自我治疗 / 负面效果 | 自己的仇敌 |
| **法术支援** | 防御 / 自我治疗 / 增益队友 / 负面效果 / 治疗队友 | 主人和友军正在打的目标 |

**法术攻击**是常规战斗位：主动索敌、走位、施法，还可以按配置用近战武器补刀。

**法术支援**不主动开战，专职给主人和同阵营生物（包括同主人的其他女仆）加血、上增益、清负面，顺手给敌人挂负面效果。

> 两个任务在 GUI 里的启用条件相同：主手或盔甲栏有注魔武器，或饰品栏有刻了法术的法术书。

### 七个行为分类

女仆的法术表按行为分成七类，**本文一律使用下表第一列的名字**。同一个分类在法术标签、游戏内配置界面、配装数据包里各有一套写法，对照如下：

| 分类（本文用名） | 法术标签 | 配置界面里的名字 | 配置键名 | 配装 `spells` 字段 |
|---|---|---|---|---|
| 攻击 | `attack_spells` | 额外的攻击法术 ID | `extraAttackSpells` | `attack` |
| 防御 | `defense_spells` | 额外的防御法术 ID | `extraDefenseSpells` | `defense` |
| 移动 | `movement_spells` | 额外的**瞬移**法术 ID | `extraMovementSpells` | `movement` |
| 自我治疗 | `support_spells` | 额外的**治疗**法术 ID | `extraSupportSpells` | `support` |
| 增益队友 | `positive_effect_spells` | 额外的**正面效果**法术 ID | `extraPositiveEffectSpells` | `positive_effect` |
| 负面效果 | `negative_effect_spells` | 额外的负面效果法术 ID | `extraNegativeEffectSpells` | `negative_effect` |
| 治疗队友 | `support_effect_spells` | 额外的**恢复效果**法术 ID | `extraSupportEffectSpells` | `support_other` |

> ⚠️ 最容易认错的一对：**自我治疗**（`support_spells`，女仆治自己）与**治疗队友**（`support_effect_spells`，配装里写作 `support_other`）。名字相近，作用对象相反。

另有两个不参与分类的**标记标签**：`summon_spells`（召唤类）与 `maid_should_recast_spells`（需要女仆多次咏唱），它们只是打标记，不决定女仆能不能放这个法术。

### 魔力

- 女仆有**独立于玩家**的魔力条，Jade 指着她就能看到。
- 上限与玩家同一套算法：法杖、法师套装上的「最大法力值」词条照样生效，也可以用配置项「最大法力值倍率」整体放大或压低。
- 自然回复默认约 **每秒 2%**，受魔力恢复词条影响。
- **被闪电击中过**是写进女仆存档的永久标记，劈中一次终身有效。打开「被雷劈过的女仆魔力恢复速度 ×100」后，这类女仆每 0.5 秒回满整条魔力，近乎无限法力——该选项**默认关闭**。

### 女仆如何选择法术

女仆每隔很短一段时间决策一次（间隔上限由「最大施法间隔刻」控制，默认最多 10 刻）：

1. **筛掉当前用不了的法术**：魔力不够或还在冷却的排除掉；如果手上有没打完的多段咏唱，则优先接着放完。
2. **给每个行为分类算权重**，加权随机抽一类，再在该类里等概率抽一个法术。

权重的几条直觉规律：

- 队友掉血越狠，「治疗队友」的权重越高，**残血队友会压过一切**；
- 附近有队友时，支援类会抢走这一轮的决策，战斗类不参与抽签；
- 自己血越少，「防御」和「移动」的权重越高；
- 看不见目标时基本不会选攻击类，转而位移绕开；
- 队友缺某个增益、或身上有能驱散的负面时，对应法术的权重会被顶到很高；
- 上一次选过防御 / 负面效果的话，这次这两类的权重会被调低，避免连续刷同一类。

索敌半径由「法术攻击最大索敌范围」（默认 64 格）决定，**带[残月烙印](#-酒狐巫法学派)的敌人会被优先选中**。女仆要逼近到「法术施放开始距离」（默认 15 格）或该法术自己的施法距离之内才会起手。

其他战斗行为：

- **走位**：距离小于射程一半时后撤，在射程内且有视线时原地绕圈；施法期间移速放慢；被命令坐下时不走位。
- **近战补刀**：由配置项「允许女仆在法术攻击时使用近战武器」控制，默认开启。

### 咏唱动画

模组把铁魔法的咏唱动作接到了车万女仆的动画系统上，使用 GeckoLib 模型的女仆施法时会播放对应动作。

模型包作者可以在自己的动画文件里定义 `iss:` 前缀的动画片段来自定义咏唱动作，键名可参考[车万女仆的 iss.animation.json](https://github.com/TartaricAcid/TouhouLittleMaid/blob/1.21/src/main/resources/assets/touhou_little_maid/animation/iss.animation.json)。

> 动画资源由铁魔法的原版动画转换而来，个别姿势可能有骨骼错位，会在后续版本继续修。

## 🍶 酒狐巫法学派

**酒狐巫法（Winefox Hex）** 是本模组新增的独立学派，有自己的伤害类型与两条属性（酒狐巫法法术强度 / 酒狐巫法抗性），可与铁魔法本体的法师套装词条混搭。

这是一个**为「玩家 + 女仆」设计的学派**：法术大多在你和女仆之间来回传递收益——你挂印起手、女仆接力引爆，你放出的披风与解控也会一并罩住身边的女仆。单人也能用，但和一队女仆一起打才是它的完整形态。

学派仍在扩充中，后续版本会继续加入新的玩法方向。

### 烙印引爆与酒涌

目前学派里最能体现「玩家 + 女仆」配合的一条线：

1. 用**残月烙印**给敌人挂印（基础 12 秒，每级 +1 秒）。
2. 让任意**酒狐巫法伤害**打在它身上——酒杯狐影、狐影伏击的咬击、狐酿炸弹直击都算。
3. 烙印立刻引爆：伤害 = 基础 6 点 + 挂印时的法术强度。
   - **玩家引爆**：半径 3 格，不连锁；
   - **自家女仆引爆**：伤害 ×1.5、半径 4 格（玩家身上的酒涌满层时 5 格），并且能**连锁引爆**下一个带印目标。
4. 每次引爆都给玩家叠一层**酒涌**：10 秒滚动刷新，最多 3 层，每层 **+10% 学派法术强度**。女仆引爆同样算在玩家头上。

烙印自然到期只会在 2 格内弱自爆一次（3 点原版魔法伤害，不叠酒涌、不触发连锁）。

也就是说：玩家负责挂印，女仆负责引爆——只要引爆能接上节奏，酒涌就不会掉层。

### 微醺

**微醺**是中性效果，不掉血，但会让中招者：

- 移动速度 −30%（按效果等级缩放）；
- 走路踉跄乱晃、朝向随机抖动（玩家的视角由客户端掌控，因此不受抖动影响）；
- 射出的箭矢等弹射物大幅打偏。

自家女仆对醉狐之雾与酒池免疫。

### 召唤女仆

学派里的一个法术：召出一队临时女仆，帮你打完眼下这一场。

- 数量随等级增长（1 级 2 只，6 级 6 只），持续 **10 分钟**。召唤期间再次施放这个法术不会多召一队，而是把已召出的女仆提前遣散。
- 每只女仆随机挑一个模型，并按召唤等级抽取装备与法术；有概率骑**扫帚**升空，在召唤者上方盘旋着施法。
- 她们**不能交互、不接受指令、不会坐下**，只跟着召唤者作战；**死亡不掉装备**，时间一到自行消散。默认还会让苦力怕主动躲着她们走。

三套内置配装（可被数据包替换或扩充）：

| 配装 | 出现权重 | 扫帚 | 定位 |
|---|---|---|---|
| **warrior** | 40 | 从不 | 攻击法术为主，护甲最厚 |
| **mage** | 35 | 允许 | 攻击 + 负面效果 + 少量防御 / 移动 |
| **support** | 25 | 允许 | 治疗队友 + 增益队友 + 少量攻击 |

按召唤等级分三层：1–2 级、3–4 级、5–6 级，层级越高护甲越全、法术越多、可携带的法术等级上限越高。

> ⚠️ **召唤女仆目前偏强，后续版本会继续给它加平衡性限制**（数量、持续时间、可携带法术等都可能调整）。
> 想现在就压低强度，可以在配置的「召唤出的女仆」一栏调整上限——默认已经限制在 3 级法术、史诗稀有度以内，也不会随机到习得制学派（即邪术）的法术；也可以直接用数据包换掉配装。

## ⚙️ 配置

全部是**服务端配置**（多人游戏以服务器上的设置为准），可以在模组列表的配置界面里直接改，也可以编辑 `<存档>/serverconfig/winefoxs_spellbooks-server.toml`。下表第二列是文件里的键名。

### 战斗与 AI

| 界面名称 | 键名 | 默认 | 说明 |
|---|---|---|---|
| 法术攻击最大索敌范围 | `maxSpellRange` | 64 | 索敌半径（8–192）。调大会增加索敌开销 |
| 法术施放开始距离 | `startSpellRange` | 15 | 起手施法距离（2–64），可被单个法术的施法距离覆盖 |

| 被雷劈过的女仆魔力恢复速度 ×100 | `lightningManaRegen` | 关 | 开启后这类女仆每 0.5 秒回满魔力 |

## 📦 数据包定制

### 排除法术

女仆能用哪些法术由**法术标签**决定。想让女仆别用某个法术（比如误伤严重的范围法术），需要用数据包把它从标签里移除。

新建 `<存档>/datapacks/<数据包名>/pack.mcmeta`：

```json
{ "pack": { "pack_format": 48, "description": "女仆法术黑名单" } }
```

再新建 `<数据包名>/data/winefoxs_spellbooks/tags/irons_spellbooks/spells/attack_spells.json`：

```json
{
  "values": [],
  "remove": [
    { "id": "irons_spellbooks:fireball" }
  ]
}
```

执行 `/reload` 即可生效——法术目录会立刻重建，已加载的女仆也会重扫一遍法术表。

**行为标签**（一个法术只属于其中一个，从它所在的那个里移除就够了，标签与分类的对照见[七个行为分类](#七个行为分类)）：

`attack_spells` · `defense_spells` · `movement_spells` · `support_spells` · `positive_effect_spells` · `negative_effect_spells` · `support_effect_spells`

想查某个法术在哪个标签里，用压缩软件打开本模组的 jar，看 `data/winefoxs_spellbooks/tags/irons_spellbooks/spells/` 这个目录——七个行为标签外加两个标记标签的 json 都在里面，内容就是本模组的默认分类，照着改成自己的数据包即可。

**标记标签**——`summon_spells` 与 `maid_should_recast_spells` 不控制可用性，从这两个里移除只会去掉召唤 / 多段咏唱标记，女仆照样会施放该法术。

> ⚠️ 配置项是在标签之后合并的，所以别把同一个法术 id 再写进 `extraAttackSpells` 之类的列表，否则会被重新加回来。

### 施法距离与附带效果

路径 `data/<命名空间>/magic_maid_spell_data/`：

- `default_casting_range.json`——女仆起手施放各法术的距离；
- `default_caused_effect.json`——声明某个法术会施加哪种药水效果，女仆据此判断该不该给队友重复上同一个增益，以及目标身上的负面该不该驱散。

两者都随 `/reload` 生效，配置文件里的同名项会叠在数据包之上。

### 召唤女仆配装

路径 `data/<命名空间>/summoned_maid_loadouts/<名称>.json`，最小骨架：

```json
{
  "weight": 40,
  "broom_mode": "default",
  "tiers": [
    {
      "conditions": [
        { "condition": "winefoxs_spellbooks:summon_level", "min": 1, "max": 2 }
      ],
      "spell_level_cap": 3,
      "weapon": {
        "rolls": 1,
        "entries": [ { "type": "tag", "expand": true, "name": "modid:weapon_tag" } ]
      },
      "armor": {
        "helmet": {
          "chance": 0.3,
          "pools": [ { "rolls": 1, "entries": [ { "type": "tag", "expand": true, "name": "modid:helmet_tag" } ] } ]
        }
      },
      "spells": {
        "attack": {
          "rolls": { "min": 1, "max": 2 },
          "entries": [ { "type": "tag", "expand": true, "name": "modid:attack_spells" } ]
        }
      }
    }
  ]
}
```

字段说明：

- `weight`——被选中的权重，`0` 表示禁用；
- `broom_mode`——`always` / `never` / `default`（走概率）；
- `model_filter`（可选）——`{ "mode": "all" | "allowlist" | "denylist", "models": [...] }`；
- `tiers[].conditions`——目前支持 `winefoxs_spellbooks:summon_level` 的 `min` / `max` 区间；
- `tiers[].spell_level_cap`——该层法术等级上限，与配置项取小；
- `tiers[].weapon` / `armor` / `spells`——物品与法术池，`rolls` 支持整数或 `{ "min": n, "max": m }`，条目用物品标签 / 法术标签引用；
- `spells` 的键就是七个行为分类：`attack`、`defense`、`movement`、`support`、`positive_effect`、`negative_effect`、`support_other`（对照见[七个行为分类](#七个行为分类)，注意 `support` 是自我治疗、`support_other` 才是治疗队友）。

内置的 `warrior.json`、`mage.json`、`support.json` 可以直接拿来当模板。

### 晨间礼物掉落

晨间礼物发什么由战利品表 `winefoxs_spellbooks:gameplay/maid_morning_gift` 决定（默认 95% 掉一个灵狐精魂），整合包可以直接覆盖它来换成自己的奖励。

## 💻 指令

需要 OP 2 级权限：

```
/wsb cast <targets> <spell> [level]
/wsb summon [target] [count] [summonLevel] [loadout] [duration] [airForce]
```

- `/wsb cast`——让指定实体施放某个法术，等级 1–10。该指令只跳过起手前的可用性检查，**魔力照扣**，所以测试前记得先把目标的魔力上限拉高。
- `/wsb summon`——不带参数就给自己召唤。`count` 1–10，`summonLevel` 1–10，`loadout` 填配装 ID（不填则随机），`duration` 是秒数（`-1` 表示永久），`airForce` 强制指定是否骑扫帚。

## ❓ 常见问题

**女仆完全不施法？** 按顺序排查：

1. 任务切到「法术攻击 / 法术支援」了吗？
2. 法术书在**饰品栏**吗？书里的法术槽刻好了吗？
3. 该法术在某个行为标签里吗？**不属于任何行为分类的法术会被直接忽略**。
4. 魔力够不够？冷却过了没？气泡显示「冷却中」就是这两者之一。
5. 敌人是不是超出了「法术攻击最大索敌范围」，或者她还没走进「法术施放开始距离」？

**女仆的范围法术总在误伤队友？** 用[数据包](#排除法术)把那个法术从行为标签里移掉，`/reload` 即可。

**改了配置怎么没生效？** 「法术兼容」一段的改动需要重启游戏；数据包相关的改动 `/reload` 就够。

**女仆为什么不会施放「召唤女仆」？** 这是有意为之——这个法术只留给玩家（以及 `/wsb summon`），女仆不会拿它再召一队女仆出来。

**支援女仆一直不救人？** 法术支援任务只照顾同阵营目标；另外她身上要有对应分类的法术（治疗队友 / 增益队友），才会切换到支援行为。
